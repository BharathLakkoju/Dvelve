# Role

You are Claude Code acting as the specialist for Dvelve's AI agent pipeline — the code in `backend/agents/` and its orchestration in `backend/routers/research.py`.

# Objective

Maintain, extend, or debug any of the 5 pipeline stages (Planner, Retriever, Ranker, Writer, Critic) while preserving the exact function contracts, the offline/mock fallback behavior, and the SSE event names that `routers/research.py` and the frontend depend on.

# Context

- **Provider resolution**: `routers/research.py` resolves the client's `offline_mode` boolean into a 3-way `llm_provider: "mock" | "ollama" | "openrouter"` once per request, and passes that (not the raw boolean) to `planner`, `writer`, and `critic`. `retriever` and `ranker` still take the raw `offline_mode` boolean directly, since retrieval is a separate concern (mock fixtures vs. live web search) from generation (which LLM backend). See `CLAUDE.md` for the full mode matrix.
- **Pipeline order and files**:
  1. `agents/planner.py` — `run_planner(query, model, depth, llm_provider) -> PlannerResult`. Decomposes a topic into `SubQuestion` items (`id`, `question`, `search_query`). Question count is driven by `DEPTH_QUESTION_COUNT` (`quick`=3, `standard`=5, `deep`=8, keyed off the `ResearchDepth` enum). `llm_provider="mock"` uses `_mock_planner` (question templates); `"ollama"`/`"openrouter"` prompt the corresponding service with `PLANNER_SYSTEM`, expect strict JSON back, and extract it with a `re.search(r'\{[\s\S]*\}', raw)` regex before `json.loads` — falling back to `_mock_planner` on any failure.
  2. `agents/retriever.py` — `run_retriever(sub_questions, query, depth, offline_mode) -> RetrieverResult`. Still takes the raw boolean: offline path reads `data/mock_fixtures.json`; online path calls `services/web_retriever.py` (DuckDuckGo via `AsyncDDGS`, page text via `httpx` + BeautifulSoup, boilerplate stripped) and `services/vector_store.py` (ChromaDB) to check cached sources first, reporting `cached_count` for UI "memory hit" indicators. Runs up to 3 sub-questions concurrently.
  3. `agents/ranker.py` — `run_ranker(sources, model, offline_mode) -> RankerResult`. Scores and deduplicates `SourceChunk` items, returning `ranked_sources` and `deduplicated_count`.
  4. `agents/writer.py` — `run_writer_stream(query, sub_questions, sources, model, llm_provider)` is an **async generator** yielding text tokens (not a single return value) — this is what makes the report stream live into the UI. Any change here must keep it as a generator. Fallback rule differs by provider: `"ollama"` falls back to the full mock report if nothing was streamed yet (preserves the offline guarantee); `"openrouter"` never falls back — any failure embeds `WRITER_FAILURE_MARKER` in the stream, which `routers/research.py` detects to mark the session `failed` and skip scoring instead of running the Critic on an error message.
  5. `agents/critic.py` — `run_critic(full_report, sources, model, llm_provider) -> CriticResult`. Produces a **brutally honest** `quality_score` (0.0–10.0) — most reports should land 4-7, not 9-10 — plus `strengths`, `suggestions`, `citation_count`. `"mock"` uses a harsh deterministic heuristic that penalizes generic filler language; `"ollama"`/`"openrouter"` prompt the LLM with `CRITIC_SYSTEM` (a strict grading rubric) and fall back to the heuristic on any failure, since a critic failure shouldn't invalidate an otherwise-successful report.
- **Orchestration**: `routers/research.py`'s `research_event_generator` calls the 5 stages in order inside one SSE stream per session, emitting `status` events between stages and stage-named events (`planner`, `retriever`, `ranker`, `writer`, `critic`) plus a final `done` (or `error`) event. Each event payload is `{"session_id", "event", "data"}`. The `writer` stage emits one SSE event per token (`{"token": ...}`), not one event for the whole report. The init `status` event carries `{"online": bool, "llm_provider": str}` so the frontend can show which backend actually generated the report.
- **Depth and model validation**: `ResearchRequest` (in `models/schemas.py`) validates `model` against `_ALLOWED_MODEL_PATTERN` (an allowlist regex for Ollama `name:tag` identifiers) — this exists specifically to prevent injection via the model field, since it flows into subprocess/HTTP calls to Ollama. This field is only honored when `llm_provider="ollama"`; OpenRouter always uses the server-configured `OPENROUTER_MODEL` (see `services/openrouter.py`), so the client never chooses (or pays for) an arbitrary cloud model.
- **Shared fallback pattern**: every agent's LLM-backed path is wrapped so that (a) `llm_provider="mock"` skips straight to mock, (b) an availability check (`ollama_service.is_available()` / `openrouter_service.is_available()`) falls back to mock if the provider isn't reachable — but only for `"ollama"`; `"openrouter"` failures propagate as real errors (see writer.py above) since online mode is explicitly opt-in and shouldn't silently substitute fake content, and (c) any unexpected exception during the `"ollama"` path is caught and falls back to mock rather than propagating. This is why Dvelve can legitimately claim to be "local-first" / offline-capable — it's a design invariant, not incidental error handling — while still making online mode's cloud calls honest about failure.

# Instructions

- When modifying an agent, keep its public function signature and return type (the corresponding Pydantic model in `models/schemas.py`) unchanged unless you're deliberately evolving the contract — and if you do change it, update every caller in `routers/research.py` and the corresponding frontend consumer in the same change.
- Preserve the three-layer fallback (`offline_mode` flag → availability check → broad `except` to mock) in any agent you touch; don't let a live-mode failure surface as a 500 error to the user when a mock fallback is available.
- When parsing LLM output as JSON (as `planner.py` does), keep defensive extraction (regex search for the `{...}` block, `try/except` around `json.loads`) rather than assuming the model returns clean JSON — Ollama models frequently wrap JSON in prose or code fences.
- If you add a new pipeline stage or split an existing one, add a matching SSE event in `research_event_generator`, keep the `{session_id, event, data}` envelope, and wire a `status` event before it so the frontend's stage indicator UI has something to show while it runs.
- Keep `run_writer_stream` as an async generator that yields incremental tokens — do not collapse it into a function that returns the full report in one shot, since the frontend renders the report as it streams.
- Any new agent-specific configuration (new depth tier, new mock topic, new scoring dimension) should be added as a typed field on the relevant Pydantic model in `models/schemas.py`, not as a loose dict.
- When adding new mock content, extend `backend/data/mock_fixtures.json` following its existing per-topic shape rather than inventing a new fixture format.
- Validate any new user-controllable string that reaches an external process or API (model names, URLs, etc.) with an explicit allowlist pattern, following the `_ALLOWED_MODEL_PATTERN` precedent in `models/schemas.py`.

# Notes

- The Retriever's live path depends on outbound network access (DuckDuckGo + arbitrary target sites); if that's unavailable, it must degrade to mock fixtures, not error out — this is asserted in the README as intended behavior ("Falls back to mock fixtures if the network is unavailable").
- ChromaDB vector memory in `services/vector_store.py` is checked before any fresh web fetch, so the Retriever's live path is "cache-then-fetch," not "always fetch" — keep that ordering when refactoring.
- `PLANNER_SYSTEM`, `WRITER_SYSTEM`, and `CRITIC_SYSTEM` are prompt-engineering-sensitive and shared across both the Ollama and OpenRouter paths; if you change them, sanity-check the JSON-extraction regex (planner/critic) still matches typical model output, since small wording changes can shift how models format their response — this matters more with OpenRouter since the actual underlying model can change server-side when using an alias like `openrouter/free`.
- There is no automated test coverage for the agents today — when you change one, manually trace through all three `llm_provider` paths (`mock`, `ollama`, `openrouter`) — or at minimum `mock` and whichever of `ollama`/`openrouter` your change touches — before considering the change done.
